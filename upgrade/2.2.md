# Guia de atualização 2.2

A versão 2.2 adiciona principalmente a adaptação ao `PHP 8`, com suporte a anotações nativas.

## Alterar a versão dos componentes Hyperf

Basta alterar uniformemente `hyperf/*` no `composer.json` para `2.2.*`.

> hyperf/engine não acompanha o número de versão do framework, portanto não precisa ser alterado

Além disso, podemos executar `composer require "hyperf/ide-helper:2.2.*" --dev` para instalar o `hyperf/ide-helper`; este componente pode nos ajudar, ao usar anotações nativas, a exibir os parâmetros que as anotações podem configurar.

Depois, basta executar `composer update -o` para concluir a atualização normalmente.

## Alterar o script de testes unitários

Adicionar a opção `--prepend test/bootstrap.php` 

```json
{
    "scripts": {
        "test": "co-phpunit --prepend test/bootstrap.php -c phpunit.xml --colors=always"
    }
}
```

## Instalar a extensão pcntl

O escaneamento de anotações da nova versão usa a extensão `pcntl`, portanto, primeiro certifique-se de que seu `PHP` tenha essa extensão instalada.

```shell
php --ri pcntl

pcntl

pcntl support => enabled
```

> Ao habilitar `grpc`, é necessário adicionar `grpc.enable_fork_support= 1;` ao `php.ini`, para dar suporte à abertura de subprocessos.

## AMQP

> Usuários que utilizam AMQP, atenção; quem não utiliza pode ignorar esta seção.

Como o componente `AMQP` foi atualizado em toda a linha, com suporte a multiplexação, a configuração também teve algumas alterações. Modifique conforme a configuração mais recente abaixo, a seu critério.

```php
<?php

return [
    'default' => [
        'host' => env('AMQP_HOST', 'localhost'),
        'port' => (int) env('AMQP_PORT', 5672),
        'user' => env('AMQP_USER', 'guest'),
        'password' => env('AMQP_PASSWORD', 'guest'),
        'vhost' => env('AMQP_VHOST', '/'),
        'concurrent' => [
            'limit' => 1,
        ],
        'pool' => [
            // Número de conexões abertas ao mesmo tempo
            // Como as conexões da nova versão suportam multiplexação, é possível atingir alta concorrência com um número muito pequeno de conexões
            'connections' => 2,
        ],
        'params' => [
            'insist' => false,
            'login_method' => 'AMQPLAIN',
            'login_response' => null,
            'locale' => 'en_US',
            'connection_timeout' => 3,
            'read_write_timeout' => 6,
            'context' => null,
            'keepalive' => true,
            'heartbeat' => 3,
            'channel_rpc_timeout' => 0.0,
            'close_on_destruct' => false,
            // Valor máximo de Channels ociosos na multiplexação; acima desse número, os Channels limitados excedentes serão fechados
            'max_idle_channels' => 10,
        ],
    ],
];

```

## Centro de configuração

> Usuários que utilizam o centro de configuração, atenção; quem não utiliza pode ignorar esta seção.

O centro de configuração foi completamente refatorado nesta versão; leia atentamente novamente a documentação correspondente.

Todos precisam importar o componente `hyperf/config-center`, com o comando abaixo:

```shell
composer require "hyperf/config-center:~2.2.0"
```

E importar o componente de dependência do driver correspondente conforme o driver usado. Por exemplo, se usar `Apollo`, será necessário importar o componente `hyperf/config-apollo`; os demais drivers são semelhantes.

Ao mesmo tempo, todas as informações de configuração relacionadas ao centro de configuração foram reunidas em `config/autoload/config_center.php`; faça a configuração correspondente conforme a nova estrutura de configuração. Se o arquivo não existir, pode criá-lo executando o comando `php bin/hyperf.php vendor:publish hyperf/config-center`.

## Centro de serviços

Usuários do componente `hyperf/service-gonvernace`: como o adaptador `consul` foi retirado desse componente, na nova versão é necessário importar adicionalmente o componente `hyperf/service-governance-consul`, com o comando abaixo:

```shell
composer require "hyperf/service-governance-consul:~2.2.0"
```

Usuários que usam `nacos` como driver do centro de serviços precisam importar o componente `hyperf/service-governance-nacos`, com o comando abaixo:

```shell
composer require "hyperf/service-governance-nacos:~2.2.0"
```

## php-cs-fixer

Se não for necessário atualizar o `php-cs-fixer` para a versão `3.0`, pode ignorar esta seção

1. Alterar o número da versão

```
"friendsofphp/php-cs-fixer": "^3.0"
```

2. Renomear o arquivo .php_cs

Renomeie para `.php-cs-fixer.php` e modifique o código correspondente conforme o registro de alterações abaixo

```diff
- return PhpCsFixer\Config::create()
+ return (new PhpCsFixer\Config())

- 'commentType' => 'PHPDoc',
+ 'comment_type' => 'PHPDoc',
```

## A compatibilidade do PHP 7.3 com o DI diminuiu um pouco

> Usuários com versões mais altas do PHP podem ignorar esta seção.

Nas versões `2.0` - `2.1`, para implementar o `AOP` atuando em objetos não gerenciados pelo `DI` (como objetos instanciados com a palavra-chave `new`), a implementação de baixo nível usava o componente `BetterReflection` para realizar as funcionalidades relacionadas. Isso trouxe uma nova experiência de programação, mas também alguns problemas difíceis de resolver, como:

- O projeto inicia muito lentamente quando não há cache de escaneamento
- Em cenários especiais, `Inject` e `Value` não têm efeito
- `BetterReflection` ainda não suporta PHP 8 (até o lançamento da 2.2)

Na nova versão, o uso do `BetterReflection` foi descontinuado, adotando-se a forma de `escaneamento por subprocesso` para resolver esses pontos problemáticos, mas em versões mais baixas do `PHP` também há algumas incompatibilidades:

Ao iniciar a aplicação com `PHP 7.3`, você pode encontrar um erro semelhante ao abaixo:

```bash
PHP Fatal error:  Interface 'Hyperf\Signal\SignalHandlerInterface' not found in vendor/hyperf/process/src/Handler/ProcessStopHandler.php on line 17

PHP Fatal error:  Interface 'Symfony\Component\Serializer\SerializerInterface' not found in vendor/hyperf/utils/src/Serializer/Serializer.php on line 46
```

Esse problema ocorre porque, no `PHP 7.3`, ao obter a reflexão por meio de `escaneamento por subprocesso`, se uma classe implementar uma `Interface` inexistente, será lançada a exceção `Interface not found`, enquanto em versões mais altas do `PHP` isso não acontece.

A solução é criar a `Interface` correspondente e importá-la normalmente. A solução para o erro acima é instalar os componentes de que se depende.

> Claro, o ideal ainda é atualizar para a versão 7.4 ou 8.0

```bash
composer require hyperf/signal

composer require symfony/serializer
```

## Sistema de arquivos

> Usuários que utilizam o sistema de arquivos, atenção; quem não utiliza pode ignorar esta seção.

A partir da versão v2.2, o Hyperf passará a suportar simultaneamente as versões `v1.0` e `v2.0` do componente `League\Flysystem`.

Se você usa a versão `v2.0` do `League\Flysystem`, os adaptadores correspondentes também precisam ser ajustados conforme a lista abaixo; para detalhes, consulte o capítulo `Sistema de arquivos`.

- Adaptador Alibaba Cloud OSS

```shell
composer require hyperf/flysystem-oss
```

- Adaptador S3

```shell
composer require "league/flysystem-aws-s3-v3:^2.0"
composer require hyperf/guzzle
```

- Adaptador Qiniu

```shell
composer require "overtrue/flysystem-qiniu:^2.0"
```

- Adaptador de memória

```shell
composer require "league/flysystem-memory:^2.0"
```

- Adaptador Tencent Cloud COS

> A configuração básica deste adaptador é ligeiramente diferente da versão `v2.0` do componente `overtrue/flysystem-cos`; modifique adequadamente conforme a configuração da versão mais recente.

```shell
composer require "overtrue/flysystem-cos:^4.0"
```
