# Guia de atualização 2.1

- A versão 2.1 adicionou principalmente o driver de baixo nível [hyperf/engine](https://github.com/hyperf/engine), permitindo que o framework `Hyperf` rode sobre `Swoole` ou `Swow`.
- A versão mínima do PHP foi alterada de 7.2 para 7.3

> O Swow é, por enquanto, uma versão de pré-visualização; use com cautela.

## Adicionar a configuração optimize-autoloader

Como o `Hyperf`, desde a versão `2.0`, precisa usar o `class_map` gerado pelo `composer`, isso exige que o usuário use `-o` para otimizar toda vez que atualizar as dependências, mas muitos usuários nunca tiveram esse hábito.
Por isso, recomendamos adicionar a configuração correspondente no `composer.json` para atender a essa necessidade.

```json
{
    "config": {
        "optimize-autoloader": true,
        "sort-packages": true
    }
}
```

## Alterar SwooleEvent

A classe `Hyperf\Server\SwooleEvent` foi renomeada para `Hyperf\Server\Event` na versão `2.1`, portanto precisamos alterar o código correspondente na configuração `server.php`.

> O SwooleEvent será oficialmente removido na versão 3.0; altere para Event o quanto antes

```php
<?php

declare(strict_types=1);

use Hyperf\Server\Event;
use Hyperf\Server\Server;

return [
    'mode' => SWOOLE_BASE,
    'servers' => [
        [
            'name' => 'http',
            'type' => Server::SERVER_HTTP,
            'host' => '0.0.0.0',
            'port' => 9501,
            'sock_type' => SWOOLE_SOCK_TCP,
            'callbacks' => [
                Event::ON_REQUEST => [Hyperf\HttpServer\Server::class, 'onRequest'],
            ],
        ],
    ],
    'callbacks' => [
        Event::ON_BEFORE_START => [Hyperf\Framework\Bootstrap\ServerStartCallback::class, 'beforeStart'],
        Event::ON_WORKER_START => [Hyperf\Framework\Bootstrap\WorkerStartCallback::class, 'onWorkerStart'],
        Event::ON_PIPE_MESSAGE => [Hyperf\Framework\Bootstrap\PipeMessageCallback::class, 'onPipeMessage'],
        Event::ON_WORKER_EXIT => [Hyperf\Framework\Bootstrap\WorkerExitCallback::class, 'onWorkerExit'],
    ],
];
```

## Paginador

Como o componente `hyperf/paginator` foi removido das dependências de `hyperf/database`, quem usa o paginador no database também precisa importar adicionalmente o componente `hyperf/paginator`.

## Alterar a versão do DBAL

Se você usa o componente `doctrine/dbal`, será necessário atualizá-lo para a versão `^3.0`.

## Remover o componente doctrine/common

O componente `doctrine/common` tem conflito de dependências com `hyperf/utils`. Portanto, é necessário remover esse componente do `composer.json`.

```bash
# Remover o componente
composer remove doctrine/common
# Atualizar
composer update "hyperf/*" -o
```

## Observações

- Procure não alterar o mecanismo de projetos antigos para Swow; se quiser usar Swow, tente fazê-lo em novos projetos. Como o Swow não é um substituto do Swoole, nem todos os cenários do Swoole têm uma solução equivalente no Swow.
