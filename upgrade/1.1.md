# Guia de atualização 1.1

A versão 1.1 adicionou muitas funcionalidades, mas algumas mudanças também envolvem ajustes no Skeleton e na estrutura dos itens de configuração. Se você já tem um projeto em uso no negócio, criado a partir do projeto Skeleton oficial, como uma aplicação 1.0, pode ajustar seu projeto skeleton conforme os pontos abaixo. Se você tem um projeto novo, basta criar um novo projeto com o comando `composer create-project hyperf/hyperf-skeleton` conforme a documentação para usar a nova estrutura de skeleton.

## Atualizar o Swoole para 4.4+

A versão 1.1 elevou o requisito mínimo de versão do Swoole de 4.3+ para 4.4+. Existem alguns detalhes de uso entre essas duas versões, mas o Hyperf já se adaptou a eles em versões anteriores; para os usuários do Hyperf, não é necessário se preocupar com essas diferenças. Elevamos o requisito mínimo de versão do Swoole principalmente para reduzir nosso fardo histórico, e o Swoole 4.4, como versão LTS (suporte de longo prazo) do Swoole, também significa maior estabilidade e confiabilidade.   

O Hyperf verifica a versão do Swoole na inicialização, mas, para unificar melhor as restrições de dependência da versão do Swoole em todos os lugares, recomendamos alterar a condição de dependência do Swoole no `composer.json` para `"ext-swoole": ">=4.4"`.

## Adicionar a constante SWOOLE_HOOK_FLAGS

No arquivo de entrada da aplicação `bin/hyperf.php` e no arquivo de entrada dos testes unitários `test/bootstrap.php`, adicione uma linha de definição de constante como abaixo:

```php
! defined('SWOOLE_HOOK_FLAGS') && define('SWOOLE_HOOK_FLAGS', SWOOLE_HOOK_ALL);
```

Referência: [Referência do arquivo de entrada](https://github.com/hyperf/hyperf-skeleton/blob/70062b7bbf29e23cda2f30680e02aa3b26ebd6f7/bin/hyperf.php#L11) [Referência do arquivo de entrada dos testes unitários](https://github.com/hyperf/hyperf-skeleton/blob/70062b7bbf29e23cda2f30680e02aa3b26ebd6f7/test/bootstrap.php#L20)

## Mover o arquivo config/dependencies.php e ajustar a estrutura de arquivos

Mova `config/dependencies.php` → `config/autoload/dependencies.php` e remova a primeira camada `dependencies` do arquivo de configuração, como abaixo:

Estrutura de arquivos 1.0:
```php
<?php
// Arquivo config/dependencies.php

return [
    'dependencies' => [
        FooInterface::class => Foo::class
    ],
];
```

Estrutura de arquivos 1.1:
```php
<?php
// Arquivo config/autoload/dependencies.php

return [
    FooInterface::class => Foo::class
];
```

## Ajustar o conteúdo do arquivo config/container.php

Como a versão 1.1 alterou a localização e a estrutura do arquivo `dependencies.php`, também precisamos ajustar o arquivo `config/container.php` para que o contêiner de injeção de dependência funcione corretamente. Ao mesmo tempo, também fornecemos uma forma mais simples de escrever o `config/container.php`: o `DefinitionSourceFactory` agrega muitos comportamentos padrão, e você só precisa substituir o conteúdo do arquivo `config/container.php` pelo conteúdo abaixo:

> A funcionalidade de cache de escaneamento de anotações é habilitada por padrão; é possível desabilitá-la alterando o primeiro parâmetro passado ao `DefinitionSourceFactory`

```php
<?php
/**
 * Initial a dependency injection container that implemented PSR-11 and return the container.
 */
declare(strict_types=1);

use Hyperf\Di\Container;
use Hyperf\Di\Definition\DefinitionSourceFactory;
use Hyperf\Utils\ApplicationContext;
use Psr\Container\ContainerInterface;

$container = new Container((new DefinitionSourceFactory(true))());
if (! $container instanceof ContainerInterface) {
    throw new RuntimeException('The dependency injection container is invalid.');
}
return ApplicationContext::setContainer($container);
```

## Ajustar o controlador WebSocket

Como a versão 1.1 alterou as restrições dos parâmetros de entrada de `onMessage` e `onOpen`, é necessário alterá-los manualmente para `Swoole\WebSocket\Server`; o código é o seguinte

```php
<?php
declare(strict_types=1);

namespace App\Controller;

use Hyperf\Contract\OnMessageInterface;
use Hyperf\Contract\OnOpenInterface;
use Swoole\Http\Request;
use Swoole\Websocket\Frame;
use Swoole\WebSocket\Server as WebSocketServer;

class WebSocketController implements OnMessageInterface, OnOpenInterface
{
    public function onMessage(WebSocketServer $server, Frame $frame): void
    {
    }

    public function onOpen(WebSocketServer $server, Request $request): void
    {
    }
}
```

## Ajustar o ConfigProvider de componentes personalizados

O `scan.path` da versão 1.0 foi ajustado para `annotations.scan.path` na versão 1.1; você precisa modificar as classes ConfigProvider de todos os componentes personalizados para se adaptar a essa mudança. Se seus componentes personalizados não envolverem configuração de escaneamento de anotações, pode ignorar este ajuste, como abaixo:

Estrutura do arquivo ConfigProvider 1.0:
```php
class ConfigProvider
{

    public function __invoke(): array
    {
        return [
            'scan' => [
                'paths' => [
                    __DIR__,
                ],
            ],
        ];
    }
}
```

Estrutura do arquivo ConfigProvider 1.1:
```php
class ConfigProvider
{

    public function __invoke(): array
    {
        return [
            'annotations' => [
                'scan' => [
                    'paths' => [
                        __DIR__,
                    ],
                ],
            ],
        ];
    }
}
```

## Ajustar o idioma de localização padrão

Se você usava antes o componente [hyperf/translation](https://github.com/hyperf/translation), verifique o item de configuração `locale` no arquivo `config/autoload/translation.php`; se estiver como `zh-CN`, altere para `zh_CN`. Na versão 1.1, unificamos o valor dessa configuração.

## Ajustar as dependências do composer.json

Como é necessário atualizar para os componentes da versão 1.1, e o projeto skeleton original dependia por padrão dos componentes da versão 1.0.x, precisamos fazer alguns ajustes nas condições de dependência: altere as dependências de todos os componentes Hyperf de `~1.0.0` para `~1.1.0`. Após a alteração, execute `composer update` para atualizar as dependências para a versão 1.1.   

É necessário atualizar todas as dependências do Hyperf para a versão 1.1 para que funcione, pois a 1.1 alterou o mecanismo de ConfigProvider ao qual os componentes se adaptam.

## Concluir a atualização

Com isso, a atualização para a 1.1 está concluída. No entanto, como todos os arquivos de baixo nível do Hyperf podem ser reescritos via DI, se você reescreveu alguns arquivos internos do framework que foram ajustados nesta atualização, ainda precisará fazer alguns ajustes conforme sua situação real.   

Se você encontrar qualquer problema durante ou após a atualização, acesse [Github Issue](https://github.com/hyperf/hyperf/issues) e envie sua issue explicando o problema encontrado; ajudaremos você a resolver o mais breve possível.
