# Guia de atualização 3.0

- A versão 3.0 alterou principalmente a versão mínima do `PHP` para `8.0`
- O framework removeu o `Doctrine Annotations` e passou a usar `PHP8 Attributes`
- O framework adicionou uma grande quantidade de restrições de tipo em variáveis de membro

## Converter todas as anotações em anotações nativas

**Atenção: esta etapa só pode ser executada na versão 2.2**

O script abaixo converterá todos os `Doctrine Annotations` em `PHP8 Attributes`.

```shell
composer require hyperf/code-generator
php bin/hyperf.php code:generate -D app
```

## Alterar a versão dos componentes Hyperf

Basta alterar diretamente todos os `hyperf/*` no `composer.json` para `3.0.*`.

> O hyperf/engine não acompanha o número de versão do framework, portanto não precisa ser alterado; basta garantir a versão ^2.1.0. Se a versão do Hyperf usada for inferior a v3.0, será necessário usar o componente engine na versão ^1.5.

Depois, basta executar `composer update -o` para concluir a atualização normalmente.

## Atualizar as classes de modelo do banco de dados

Como a classe base de modelo passou a ter suporte a tipos em variáveis de membro, é necessário usar o script abaixo para atualizá-la para a nova versão.

```shell
composer require hyperf/code-generator
php vendor/bin/regenerate-models.php $PWD/app/Model
```

## Logger

A versão 3.x do `monolog/monolog` usa novos recursos do PHP8.1, portanto algumas classes precisam de modificações especiais

Basta alterar `array $record` para `array|LogRecord $record` para ficar compatível com a versão 3.x. O código de exemplo é o seguinte

```php
<?php

declare(strict_types=1);

namespace App\Kernel\Log;

use Hyperf\Context\Context;
use Hyperf\Coroutine\Coroutine;
use Monolog\LogRecord;
use Monolog\Processor\ProcessorInterface;

class AppendRequestIdProcessor implements ProcessorInterface
{
    public const REQUEST_ID = 'log.request.id';

    public function __invoke(array|LogRecord $record)
    {
        $record['extra']['request_id'] = Context::getOrSet(self::REQUEST_ID, uniqid());
        $record['extra']['coroutine_id'] = Coroutine::id();
        return $record;
    }
}

```

## Command

A partir da versão `3.0`, os comandos de linha de comando ativam por padrão os listeners de eventos. Portanto, quando houver um listener escutando eventos de `Command` e executando lógica de `AMQP` ou outra multiplexação, o processo poderá não conseguir encerrar.

Soluções

- Método 1:

Ao executar o comando, adicione a opção `--disable-event-dispatcher`

- Método 2:

Adicionar um listener

```php
<?php

declare(strict_types=1);

namespace App\Listener;

use Hyperf\Command\Event\AfterExecute;
use Hyperf\Coordinator\Constants;
use Hyperf\Coordinator\CoordinatorManager;
use Hyperf\Event\Annotation\Listener;
use Hyperf\Event\Contract\ListenerInterface;

#[Listener]
class ResumeExitCoordinatorListener implements ListenerInterface
{
    public function listen(): array
    {
        return [
            AfterExecute::class,
        ];
    }

    public function process(object $event): void
    {
        CoordinatorManager::until(Constants::WORKER_EXIT)->resume();
    }
}
```

## Substituir Hyperf\Utils\Context

- Como o namespace do Context foi alterado na 3.0, é necessário substituir globalmente `Hyperf\Utils\Context` => `Hyperf\Context\Context`.

## Iniciar o serviço

Em seguida, basta iniciar o serviço para identificar os pontos incompatíveis e corrigi-los um a um.

- As variáveis de membro do AMQP Consumer e Producer receberam tipos
- O método `process` do listener ganhou o tipo de retorno `void`
- A anotação CircuitBreaker alterou o parâmetro `$timeout` para `$options.timeout`
- As variáveis de membro da fila assíncrona Async Queue receberam tipos
- Na fila assíncrona, o campo `event->message` foi alterado para tipo não público, sendo necessário usar `event->getMessage()` para leitura.

## gRPC

O framework, seguindo a especificação `gRPC`, alterou o `Http status` retornado pelo `gRPC Server` para fixo em 200, com o `gRPC Server` retornando o `status code` correspondente. Se você usa `gRPC` antes da atualização, não deixe de atualizar os serviços relacionados para a versão `3.x`; caso contrário, quando ocorrer uma exceção na requisição, o lado oposto não conseguirá analisar o erro corretamente.
