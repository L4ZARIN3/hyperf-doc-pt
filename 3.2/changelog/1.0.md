# Registro de atualização de versões

# v1.0.16 - 2019-09-20

## Adicionado

- [#565](https://github.com/hyperf/hyperf/pull/565) Adiciona suporte ao parâmetro de configuração `options` do cliente Redis;
- [#580](https://github.com/hyperf/hyperf/pull/580) Adiciona o recurso de controle de concorrência de corrotinas; por meio de `Hyperf\Utils\Coroutine\Concurrent` é possível limitar a quantidade máxima de corrotinas em execução simultânea dentro de um bloco de código;

## Alterações

- [#583](https://github.com/hyperf/hyperf/pull/583) Quando `BaseClient::start` falha, é lançada a exceção `Hyperf\GrpcClient\Exception\GrpcClientException`;
- [#585](https://github.com/hyperf/hyperf/pull/585) Quando uma Task enviada para execução ao TaskWorker falha, a exceção é devolvida ao processo Worker;

## Correções

- [#564](https://github.com/hyperf/hyperf/pull/564) Corrige o problema de valor de retorno incorreto de `Coroutine\Http2\Client->send` em algumas situações;
- [#567](https://github.com/hyperf/hyperf/pull/567) Corrige o problema de não ser possível gerar a classe proxy quando o name da configuração do consumidor JSON RPC não é uma interface;
- [#571](https://github.com/hyperf/hyperf/pull/571) Corrige o problema de contaminação da variável de corrotina de `stopPropagation` do ExceptionHandler;
- [#579](https://github.com/hyperf/hyperf/pull/579) Inicializa dinamicamente o MetaData do `snowflake`, corrigindo principalmente o problema de, ao usar o Snowflake no modo de comando, por exemplo no comando `di:init-proxy`, haver conexão ao servidor Redis até o timeout;

# v1.0.14 - 2019-09-05

## Adicionado

- [#389](https://github.com/hyperf/hyperf/pull/389) [#419](https://github.com/hyperf/hyperf/pull/419) [#432](https://github.com/hyperf/hyperf/pull/432) [#524](https://github.com/hyperf/hyperf/pull/524) Adiciona o componente oficial Snowflake. Snowflake é um algoritmo de geração de ID globalmente único e distribuído proposto pelo Twitter, e o componente [hyperf/snowflake](https://github.com/hyperf/snowflake) implementa esse algoritmo e foi projetado para ser fácil de usar, além de oferecer, em seu design, boa extensibilidade, sendo possível converter facilmente esse componente em outras variantes baseadas no algoritmo Snowflake;
- [#525](https://github.com/hyperf/hyperf/pull/525) Adiciona um método `download()` a `Hyperf\HttpServer\Contract\ResponseInterface`, oferecendo um retorno de resposta de download conveniente;

## Alterações

- [#482](https://github.com/hyperf/hyperf/pull/482) Ao gerar arquivos de modelo, quando a opção `refresh-fillable` está definida, a propriedade `fillable` do modelo é regenerada; ao mesmo tempo, por padrão, esse comando não sobrescreverá mais a geração da propriedade `fillable`;
- [#501](https://github.com/hyperf/hyperf/pull/501) Quando a propriedade `path` da anotação `Mapping` é uma string vazia, a rota passa a ser `/prefix`;
- [#513](https://github.com/hyperf/hyperf/pull/513) Se o projeto definir a propriedade `app_name`, o nome do processo passará a incluir automaticamente esse nome;
- [#508](https://github.com/hyperf/hyperf/pull/508) [#526](https://github.com/hyperf/hyperf/pull/526) Ao executar o método `Hyperf\Utils\Coroutine::parentId()` em um ambiente sem corrotina, será retornado o valor `null`;

## Correções

- [#479](https://github.com/hyperf/hyperf/pull/479) Corrige o problema de tipo de retorno incorreto quando a propriedade `host` do cliente Elasticsearch está configurada incorretamente;
- [#514](https://github.com/hyperf/hyperf/pull/514) Corrige o problema de falha na autenticação quando a senha do Redis é configurada como string vazia;
