# v2.0 - 2020-06-22

## Principais funcionalidades

1. Reestruturado o componente [hyperf/di](https://github.com/hyperf/di), especialmente com otimizações para AOP e anotações; na versão 2.0, esse componente usa um mecanismo de carregamento totalmente novo para oferecer suporte à funcionalidade AOP.
    1. Em comparação com a versão 1.x, a funcionalidade mais notável é que agora você pode interceptar com AOP uma classe instanciada de qualquer forma; por exemplo, na versão 1.x você só podia interceptar classes criadas pelo contêiner DI e não podia interceptar uma classe instanciada com a palavra-chave `new`, mas na versão 2.0 isso funciona. Ainda existem algumas exceções: você continua não podendo interceptar as classes usadas na fase de inicialização para fornecer a funcionalidade AOP;
    2. Na versão 1.x, AOP só podia atuar em classes comuns e não suportava classes `Final`, mas na versão 2.0 você pode fazer isso;
    3. Na versão 1.x, você não podia usar no construtor da classe atual o valor de uma propriedade de membro de classe marcada com as anotações `@Inject` ou `@Value`, mas na versão 2.0 você pode fazer isso;
    4. Na versão 1.x, apenas objetos criados pelo contêiner DI podiam fazer as anotações `@Inject` e `@Value` funcionarem; objetos criados com a palavra-chave `new` não funcionavam, mas na versão 2.0 todos funcionam;
    5. Na versão 1.x, ao usar anotações, você precisava definir o namespace da anotação para especificar a classe de anotação usada, mas na versão 2.0 você pode fornecer um alias para qualquer anotação, de modo que, ao usá-la, possa usar o alias diretamente sem importar o namespace da classe de anotação. Por exemplo, você pode marcar a anotação `@Inject` diretamente em qualquer propriedade de classe sem escrever `use Hyperf\Di\Annotation\Inject;`;
    6. Na versão 1.x, a classe proxy criada era uma subclasse da classe alvo; esse mecanismo de implementação fazia com que algumas constantes mágicas retornassem informações da subclasse proxy em vez das informações da classe alvo, mas na versão 2.0 a classe proxy mantém o mesmo nome de classe e estrutura de código da classe alvo;
    7. Na versão 1.x, quando o cache da classe proxy existia, ele não era regenerado, mesmo que o código-fonte tivesse mudado; esse mecanismo ajudava a melhorar o tempo de varredura, mas também causava inconvenientes na fase de desenvolvimento. Na versão 2.0, o cache da classe proxy muda automaticamente conforme as alterações do código-fonte, o que reduz bastante a carga mental na fase de desenvolvimento;
    8. Adicionada a propriedade de prioridade `priority` às classes Aspect, permitindo agora organizar a ordem entre vários Aspects;
    9. Na versão 1.x, você só podia definir uma classe Aspect por meio de uma classe anotada com `@Aspect`, mas na versão 2.0 você também pode definir classes Aspect por meio de arquivos de configuração e ConfigProvider;
    10. Na versão 1.x, ao usar a funcionalidade de carregamento lazy de dependências, você precisava registrar um listener `Hyperf\Di\Listener\LazyLoaderBootApplicationListener`, mas na versão 2.0 você pode usar essa funcionalidade diretamente sem nenhuma ação de registro;
    11. Adicionada a opção de configuração `annotations.scan.class_map`, por meio da qual você pode substituir qualquer classe pela sua própria classe sem precisar fazer nenhuma alteração no uso;

## Alterado

- [#705](https://github.com/hyperf/hyperf/pull/705) Unificada a forma de tratamento de exceções HTTP: agora uma classe dependente `Hyperf\HttpMessage\Exception\HttpException` é lançada uniformemente em vez de responder diretamente no `Dispatcher`, e também é fornecido o processador de exceções `Hyperf\HttpServer\Exception\Handler\HttpExceptionHandler` para tratar esse tipo de exceção;
- [#1846](https://github.com/hyperf/hyperf/pull/1846) Quando você adiciona a biblioteca `symfony/serializer` ao require, a classe de implementação de `Hyperf\Contract\NormalizerInterface` não é mais mapeada automaticamente; você precisa adicionar esse mapeamento manualmente, conforme abaixo:

```php
use Hyperf\Utils\Serializer\SerializerFactory;
use Hyperf\Utils\Serializer\Serializer;

return [
    Hyperf\Contract\NormalizerInterface::class => new SerializerFactory(Serializer::class),
];
```
